Vortex / private laptop runtime

Hermes Worker
kurulum defteri.

Mevcut WSL worker'ını güvenli pakete çevir. Yeni laptopta sıfırdan kur. Docker, Hermes, CLIProxy ve Vortex.Server zincirini kanıtla. Kullanıcı verisi ve gizli anahtarlar hiçbir aşamada taşınmaz.

Tek iş:
Desktop mesajı Worker'a ulaşır; Worker izole kullanıcı workspace'inde Hermes çalıştırır; sonuç Server üzerinden Desktop'a döner.

Başlamadan

Gizli değerleri arşive koyma.

Kural: Gerçek VORTEX_WORKER_TOKEN, OPENAI_API_KEY, CLIProxy anahtarı, worker.env, hermes.env, hermes-config.yaml, data/, kullanıcı workspace'i, log ve database taşıma paketine girmez. Yeni laptopta secret'lar güvenli kanaldan yeniden yazılır.

Bu rehber yalnız private worker paketi içindir. Public GitHub release içine Worker source, WSL runtime, secret, Docker state veya kullanıcı verisi koyma.

1
Mevcut laptop / WSL

Taşınabilir Worker paketi üret.

Hedef: başka laptopta Worker build edebilmek. Paket yalnız kaynak, Docker recipe ve örnek ayar taşır. Mevcut runtime state taşımaz.

1.1 Mevcut worker runtime haritası

/home/<user>/vortex-worker/
├── current/                         # aktif publish release (symlink olabilir)
├── releases/<release-id>/           # eski/yeni publish release'ler
├── secrets/                         # TAŞIMA: yasak
│   ├── worker.env                   # Worker token + server adresi
│   ├── hermes.env                   # API/CLIProxy ayarları
│   └── hermes-config.yaml           # provider/model config
└── data/                            # TAŞIMA: yasak
    ├── logs/worker.log
    └── users/<server-workspace-id>/
        ├── workspace/               # kullanıcı çalışma alanı
        ├── hermes-home/
        ├── memory/  automations/  artifacts/  temp/  metadata/

1.2 WSL içinde güvenli allowlist staging

Vortex kaynak checkout yolunu kendine göre değiştir. Örnek: Windows diskteki repository.

export SOURCE="/mnt/c/Users/<WINDOWS_KULLANICISI>/Desktop/<VORTEX_KAYNAK_KLASORU>"
export KIT="$HOME/vortex-worker-kit"
rm -rf "$KIT"
mkdir -p "$KIT/source" "$KIT/image"

cp -a "$SOURCE/Vortex.HermesWorker" "$KIT/source/"
cp -a "$SOURCE/Vortex.Shared" "$KIT/source/"
cp -a "$SOURCE/docker/hermes" "$KIT/source/"
cp -a "$SOURCE/deploy/wsl" "$KIT/source/"
cp -a "$SOURCE/Directory.Build.props" "$KIT/source/"
find "$SOURCE" -maxdepth 1 -name '*.sln' -type f -exec cp -a {} "$KIT/source/" \;
find "$SOURCE" -maxdepth 1 -name 'NuGet*.config' -type f -exec cp -a {} "$KIT/source/" \;
Bu komuttan sonra oluşan klasör: /home/<LINUX_KULLANICISI>/vortex-worker-kit/. İçinde taşınabilir Worker kaynakları source/, Docker image export'u için boş image/ klasörü bulunur. Henüz taşınacak tek arşiv oluşmaz.

1.3 Arşivden yasak dosyaları doğrula

find "$KIT" -type f \( -iname '*.env' -o -iname '*secret*' -o -iname '*token*' -o -iname '*.db' -o -iname '*.sqlite*' -o -path '*/data/*' -o -path '*/logs/*' \) -print
# Beklenen: çıktı yok.
Not: Bu ad kontrolüdür. grep ile gerçek key değerini ekrana/loga basma. Secret taraması şüpheli dosya bulursa dosyayı paketten çıkar; anahtar değerini paylaşma.

1.6 ZIP yoksa ve Windows'tan dosyayı alma

zip: command not found görürsen TAR paketin yine geçerlidir. ZIP checksum dosyası oluşmuşsa ama ZIP oluşmamışsa önce yanlış checksum dosyasını sil, sonra ZIP aracını kur.

rm -f "$HOME/vortex-worker-kit.zip.sha256"
sudo apt update
sudo apt install -y zip

cd ~
zip -r vortex-worker-kit.zip vortex-worker-kit
sha256sum vortex-worker-kit.zip > vortex-worker-kit.zip.sha256
Dizin notu: ~, Linux kullanıcının home dizinidir: /home/<LINUX_KULLANICISI>. Home'a dönmek için cd ~ yaz; cd home yazma.

Windows Explorer'dan arşivleri almak için önce Yönetici olmayan PowerShell'de dağıtım adını bul:

wsl -l -v

Sonra Explorer adres çubuğuna şu yolu gir:

\\wsl$\<DAGITIM_ADI>\home\<LINUX_KULLANICISI>\

Örnek: \\wsl$\Ubuntu\home\<LINUX_KULLANICISI>\. Burada vortex-worker-kit.tar.gz, checksum dosyaları ve oluşturduysan ZIP dosyası bulunur.

2.4 Worker kit aç ve publish et

mkdir -p "$HOME/vortex-worker"
cd "$HOME/vortex-worker"
# Harici disk/Windows Downloads konumunu kendi dosyana göre değiştir.
tar -xzf /mnt/c/Users/<WINDOWS_KULLANICISI>/Downloads/vortex-worker-kit.tar.gz
mv vortex-worker-kit/source source

cd "$HOME/vortex-worker/source"
dotnet publish Vortex.HermesWorker/Vortex.HermesWorker.csproj \
  -c Release -o "$HOME/vortex-worker/releases/$(date -u +%Y%m%dT%H%M%SZ)"
ln -sfn "$(readlink -f "$HOME/vortex-worker/releases/$(ls -1 "$HOME/vortex-worker/releases" | tail -n1)")" "$HOME/vortex-worker/current"
Daha güvenli alternatif: publish dizin adını önce değişkene al, sonra ln -sfn ile current linkini o release'e yönlendir. Bu link service'in çalıştırdığı sürümdür.

docker image inspect vortex-hermes:0.18.2 >/dev/null && echo IMAGE_OK

2.6 CLIProxy erişimi ve Hermes one-shot

Worker Docker container içinden WSL-local CLIProxy'ye host.docker.internal üzerinden ulaşır. CLIProxy önce kendi laptopunda hazır olmalı; public LAN portu açma.

# CLIProxy portunu kendi kurulumuna göre değiştir.
docker run --rm --entrypoint sh \
  --add-host host.docker.internal:host-gateway \
  vortex-hermes:0.18.2 -lc \
  'python3 -c "import urllib.request; print(urllib.request.urlopen(\"http://host.docker.internal:20128/api/v1\", timeout=10).status)"'
# Beklenen: 200

Sonra private Hermes config ve env hazır olduktan sonra kısa model testi çalıştır. Bu test ayrı geçici workspace kullanır; kullanıcı workspace'ine bağlanmaz.

mkdir -p /tmp/vortex-hermes-test/workspace /tmp/vortex-hermes-test/hermes-home
cp "$HOME/vortex-worker/secrets/hermes-config.yaml" /tmp/vortex-hermes-test/hermes-home/config.yaml
cp "$HOME/vortex-worker/secrets/hermes.env" /tmp/vortex-hermes-test/hermes-home/.env

timeout 70s docker run --rm --network bridge \
  --add-host host.docker.internal:host-gateway \
  --workdir /workspace --memory 512m --memory-swap 512m --pids-limit 128 \
  --mount type=bind,source=/tmp/vortex-hermes-test/workspace,target=/workspace \
  --mount type=bind,source=/tmp/vortex-hermes-test/hermes-home,target=/home/hermes/.hermes \
  --env HERMES_HOME=/home/hermes/.hermes --env HOME=/home/hermes \
  vortex-hermes:0.18.2 -z "Selam. Tek cümle Türkçe yanıt ver."
echo "Çıkış kodu: $?"

3
Server bağlantısı

Kuyruğa bağlan. Kullanıcıları ayır.

Desktop → Vortex.Server /api/agent/chat → AgentJobs queue → Laptop Worker → izole Docker Hermes → Server sonucu kaydeder → Desktop SSE sonucu gösterir

3.1 Private environment dosyaları

Bu dosyalar archive'a girmez. İzinleri yalnız Linux kullanıcısına açık olmalı.

mkdir -p "$HOME/vortex-worker/secrets" "$HOME/vortex-worker/data"
chmod 700 "$HOME/vortex-worker/secrets"

cat > "$HOME/vortex-worker/secrets/worker.env" <<'EOF'
VORTEX_SERVER_URL=https://<SUNUCU_ALANI>
VORTEX_WORKER_ID=laptop-hermes-worker
VORTEX_WORKER_TOKEN=<SERVER_WORKER_SERVICE_TOKEN_ILE_AYNI_DEGER>
VORTEX_WORKER_DATA=/home/<LINUX_KULLANICISI>/vortex-worker/data
VORTEX_HERMES_EXECUTION_MODE=docker
VORTEX_DOCKER_HERMES_IMAGE=vortex-hermes:0.18.2
HERMES_CONFIG_SEED_PATH=/home/<LINUX_KULLANICISI>/vortex-worker/secrets/hermes-config.yaml
HERMES_ENV_SEED_PATH=/home/<LINUX_KULLANICISI>/vortex-worker/secrets/hermes.env
VORTEX_DOCKER_MEMORY_LIMIT_MB=512
VORTEX_DOCKER_MEMORY_SWAP_LIMIT_MB=512
VORTEX_DOCKER_PIDS_LIMIT=128
VORTEX_REQUIRE_PRIVATE_SERVER_ENDPOINT=false
EOF
chmod 600 "$HOME/vortex-worker/secrets/worker.env"

hermes.env yalnız gerekli provider/CLIProxy ayarlarını içerir. hermes-config.yaml model/provider config'tir. Gerçek değerleri komut geçmişine veya sohbet ekranına yapıştırma.

3.2 Server ile zorunlu eşleşme

  • VORTEX_WORKER_ID = Server Worker:AllowedWorkerId
  • VORTEX_WORKER_TOKEN = Server Worker:ServiceToken
  • VORTEX_SERVER_URL = public HTTPS veya doğrulanmış private/Tailscale Server endpoint

İlk iki değer farklıysa Worker heartbeat isteği 401 Unauthorized alır. Server Worker'ı offline görür, işler Queued kalır.

3.3 Repository source ile WSL Worker aynı mı?

Varsayma: Repository içindeki Vortex.HermesWorker/ source kodudur. WSL'de çalışan Worker ise publish edilmiş binary'dir: /home/<LINUX_KULLANICISI>/vortex-worker/current/Vortex.HermesWorker.dll. current bir symbolic link'tir ve bir releases/<RELEASE_ID>/ klasörünü gösterir. Source sonradan değiştiyse, eski release otomatik güncellenmez.
WORKER_HOME="$HOME/vortex-worker"
readlink -f "$WORKER_HOME/current"
sha256sum "$WORKER_HOME/current/Vortex.HermesWorker.dll"
systemctl --user status vortex-hermes-worker --no-pager -l
systemctl --user cat vortex-hermes-worker

Bu komutlar aktif release'i, binary hash'ini ve service'in gerçekten hangi DLL'i çalıştırdığını gösterir. Source ile binary'nin kesin aynı olduğunun güvenilir kanıtı: aynı source commit'ten yeni publish üretmek ve current linkini bu release'e taşımaktır.

3.4 Source'tan güvenli güncelleme ve rollback

Repository içinde secret-free update helper bulunur: Vortex.HermesWorker/publish-wsl-worker.sh. Script token/API key yazmaz veya göstermez; yalnız private worker.env varlığını ve 600 iznini kontrol eder, yeni release publish eder, current linkini değiştirir ve service'i restart eder.

# Worker kit/source bulunduğun yere göre değiştir.
cd "$HOME/vortex-worker/source"
chmod +x Vortex.HermesWorker/publish-wsl-worker.sh
./Vortex.HermesWorker/publish-wsl-worker.sh "$PWD"

readlink -f "$HOME/vortex-worker/current"
systemctl --user status vortex-hermes-worker --no-pager -l
curl -s https://<SUNUCU_ALANI>/health/worker

Eski release silinmez. Yeni release sorun çıkarırsa önce eski hedefi listele, sonra linki eski release'e döndür:

ls -1dt "$HOME/vortex-worker/releases"/*
ln -sfn "$HOME/vortex-worker/releases/<ESKI_RELEASE_ID>" "$HOME/vortex-worker/current"
systemctl --user restart vortex-hermes-worker
readlink -f "$HOME/vortex-worker/current"

3.5 systemd --user service

mkdir -p "$HOME/.config/systemd/user"
cat > "$HOME/.config/systemd/user/vortex-hermes-worker.service" <<'EOF'
[Unit]
Description=Vortex Hermes Worker
After=network-online.target docker.service
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=%h/vortex-worker/current
EnvironmentFile=%h/vortex-worker/secrets/worker.env
ExecStart=/usr/bin/dotnet %h/vortex-worker/current/Vortex.HermesWorker.dll
Restart=on-failure
RestartSec=10
NoNewPrivileges=true
PrivateTmp=true

[Install]
WantedBy=default.target
EOF

systemctl --user daemon-reload
systemctl --user enable --now vortex-hermes-worker
systemctl --user status vortex-hermes-worker --no-pager -l

WSL kapansa bile user service devam etsin istiyorsan:

loginctl enable-linger "$USER"

3.6 Public paylaşım güvenlik sınırı

Public release içine asla koyma: gerçek server alan adı/IP adresi, VORTEX_WORKER_TOKEN, Worker:ServiceToken, OPENAI_API_KEY, CLIProxy key, worker.env, hermes.env, hermes-config.yaml, data/, logs, Docker container/volume state, database veya kullanıcı workspace'i.

Public-safe içerik yalnız source, Dockerfile, örnek worker.env template'i, secret-free vortex-hermes-worker.service.example, publish-wsl-worker.sh ve bu rehberdir. Örneklerde yalnız <SUNUCU_ALANI>, <TOKEN> gibi placeholder kullan. Bununla public rehber, Server IP/hostname veya hangi API sağlayıcısının kullanıldığı bilgisini sızdırmaz.

3.7 Server readiness kanıtı

curl -s https://<SUNUCU_ALANI>/health/worker
{
  "serverHealthy": true,
  "workerId": "laptop-hermes-worker",
  "workerConnected": true,
  "hermesReady": true,
  "modelReady": true,
  "storageHealthy": true,
  "status": "ModelReady"
}
Bu beş durum true ise: Server Worker heartbeat alıyor; Docker/Hermes readiness ve data root sağlıklı. Sonra Desktop'tan Selam gönder; akış Queued → Claimed → Running → Completed olmalı.

3.8 Her kullanıcı ayrı workspace

Server her Agent Job için server-owned WorkspaceId gönderir. Worker yalnız aşağıdaki alanda workspace üretir:

/home/<LINUX_KULLANICISI>/vortex-worker/data/users/<SERVER_WORKSPACE_ID>/
├── workspace/
├── hermes-home/
├── memory/
├── automations/
├── artifacts/
├── temp/
└── metadata/

Bir kullanıcının workspace'i diğer kullanıcının ID'siyle paylaşılmaz. Worker path doğrulaması yapar; workspace dışına çıkmayı, reparse/symlink kaçışlarını ve uyumsuz policy'yi reddeder. Bu dizinler data/state kabul edilir: taşınmaz, public release'e girmez.

Owner/Admin server diagnostics

Owner, Administrator veya Support token ile aktif Worker ve terminal olmayan jobları okuyabilirsin:

curl -s -H "Authorization: Bearer <OWNER_ADMIN_SUPPORT_TOKEN>" \
  https://<SUNUCU_ALANI>/api/diagnostics/worker

Bu endpoint Worker heartbeat/readiness ile Queued, Claimed, Running jobların deneme sayısını, son heartbeat'ini ve hata kodunu verir. Tokenı shell history'de bırakmamak için güvenli local secret mekanizması kullan.

  • Yeni API key'i yalnız hermes.env gibi private secret dosyasına yaz.
  • Eski chat/terminal/paste kayıtlarını secret deposu sayma; geçmişteki değeri geçersiz bırak.
